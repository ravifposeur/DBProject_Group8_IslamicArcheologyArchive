# Database Schema Definition

The "schema.sql" file contains the SQL DDL (Data Definition Language) statements to create the database structure for the project. This schema is a direct implementation of the logical diagram.

## DBMS (Database Management System)

This schema is written for **PostgreSQL**. It uses specific features like `GENERATED BY DEFAULT AS IDENTITY` for primary keys and `CREATE TYPE ... AS ENUM`.

## Implementation Notes

While the schema is a straightforward translation of the diagram, the following additions and normalizations were made for a functional system.

* **New ENUM Types**: Two custom `ENUM` types were created to standardize values.
    * `role_enum`: ('kontributor', 'verifikator', 'administrator') - Used by `pengguna`.
    * `status_enum`: ('pending', 'verified', 'rejected') - Used for content verification.

* **User/Auth Table (`pengguna`)**: The `pengguna` table was added to manage users, roles (using `role_enum`), and authentication.

* **Verification & Reporting Columns**: To support a content verification, the following columns were added.
    * `situs_arkeologi`: added `status_verifikasi` (using `status_enum`) and `pengguna_pelapor_id`.
    * `objek_temuan`: added `status_verifikasi` (using `status_enum`) and `pengguna_pelapor_id`.

* **Address Normalization (3NF)**: The address fields in `situs_arkeologi` were normalized to achieve Third Normal Form (3NF) and reduce data redundancy. This involved creating separate tables:
    * `kota_kabupaten`
    * `kecamatan` (links to `kota_kabupaten`)
    * `desa_kelurahan` (links to `kecamatan`)
    * The `situs_arkeologi` table now only stores `jalan_dusun` and a foreign key (`desa_kelurahan_id`).
